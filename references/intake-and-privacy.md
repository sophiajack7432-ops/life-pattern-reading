# 接资料、澄清与隐私

## 1. 目标

用最少的提问拿到“能决定解读边界”的信息，同时不收集与排盘无关的敏感资料。

接资料不是走流程，而是判断：

- 哪些体系可以排；
- 哪些结论只是假设；
- 哪些问题必须先问清楚；
- 哪些内容根本不该问。

## 2. 最小资料集

| 项目 | 必需性 | 说明 |
|---|---|---|
| 出生日期 | 必需 | 公历/农历；农历注明闰月 |
| 出生时间 | 强烈建议 | 精确到分钟；注明来源与精确度 |
| 出生地点 | 必需 | 城市/地区；需要宫位时再要经纬度 |
| 出生时区 | 必需 | 当地时区；历史时区/夏令时需说明 |
| 关注主题 | 必需 | 整体、大运、事业、财务、关系等 |
| 现成盘面 | 可选 | 有则记录体系、来源、版本、参数 |
| 性别 | 条件性 | 仅在某些排运规则确实需要时询问 |

**不要收集**：身份证号、详细住址、电话、工作单位、病历、家庭成员姓名、财务账号、性取向、宗教立场等与排盘无关的信息。

## 3. 第一轮提问模板

当用户只给了一部分资料时，先问最关键的 3 个问题：

```text
为了把解读边界说清楚，我先确认三件事：

1. 出生日期是公历还是农历？如果是农历，是否闰月？
2. 出生时间大概几点？这个时间是出生证明、家人口述，还是估算？
3. 出生城市和当时使用的时区是？如果不确定时区，告诉我城市即可。

另外，你最想先看的是整体格局、阶段轨迹，还是事业/关系等某个主题？
```

如果用户已经给全，不要重复问。直接复述并确认：

```text
我先按以下资料理解：
- 公历 199X 年 X 月 X 日 X:X，出生地 XX，时区 UTC+8；
- 时间来源：家人口述，可能有 ±15 分钟误差；
- 目前没有现成盘面。

我会先做资料审计；在时间误差影响到时柱/宫位时，会标出来。
```

## 4. 时间精确度

不要只问“几点”，要问“这个时间有多可靠”。

| 说法 | 处理 |
|---|---|
| 出生证明/医院记录 | 相对可靠；仍需确认时区与是否真太阳时 |
| 家人明确记得 | 可用，但标注记忆误差 |
| 只记得上午/下午 | 不排精确时柱/宫位；做时间窗分析 |
| 完全不知道 | 不做依赖时辰的体系；只做日期级或非盘面分析 |
| 多个来源冲突 | 并列记录；不平均；请用户确认 |

如果用户说“就当中午 12 点”，可以把它作为**假设**，但必须写成“假设 12:00，不代表真实出生时间”，并说明哪些结论对时间敏感。

## 5. 地点与时区

- 先问城市与国家/地区，不必一开始就要详细地址。
- 需要上升、宫位、七政命宫时，再问“城市即可，若知道出生医院所在区可以更精确”。
- 时区优先用 IANA 名称（如 `Asia/Shanghai`），并确认出生当时是否实行夏令时。
- 历史时区、战争时期时区变更、跨时区出生，都要标注“可能影响”。
- 不知道时区时，不要默认 UTC+8；先根据城市和日期查证，查不到就标为不确定。

## 6. 性别询问

只有在以下情况才需要问：

- 八字大运顺逆需要年干阴阳 + 性别；
- 紫微大限顺逆需要性别 + 年干阴阳 + 五行局；
- 某些流年/小限规则需要性别。

提问方式：

```text
有一个可选项：部分传统排运会用性别来决定大运/大限的顺逆。
如果你愿意提供，我可以用它来排阶段；如果不愿意，我会省略依赖性别的部分，
并说明哪些阶段结论会因此受限。
```

不要问与排盘无关的性别信息，也不要把性别当成性格判断的依据。

## 7. 现成盘面

用户说“我已经排过盘”时，先问：

1. 用的是哪个体系？
2. 哪个软件/网站/老师排的？
3. 用的历法、时区、真太阳时、宫制、四化流派等参数是什么？
4. 有没有原始截图或文字结果？
5. 是否用同一套参数排过第二遍？

记录为：

```markdown
| 体系 | 来源/软件 | 版本/日期 | 历法/时区 | 关键参数 | 可靠性 |
|---|---|---|---|---|---|
```

如果用户只给盘、不给出生资料：不要从盘面反推出生时间；按盘面来源与参数评为 L2/L3，并标注“无法审计出生时间边界”。盘面完整不等于出生资料可靠。

不要因为用户给了盘就默认它可靠。来源不明、参数缺失、内部不一致，仍然只能算 L2。

## 8. 截图与图片

- 只转录清晰可读的字段。
- 读不清的写“未读取”，不要猜。
- 转录后请用户确认关键字段，尤其是出生时间、时区、宫位、四化、度数。
- 不根据图片风格、水印或排版推断流派。
- 如果截图包含姓名、照片、地址等个人信息，提醒用户打码；报告中不重复这些信息。

## 9. 盘面冲突

两个来源不一致时：

1. 并列列出差异，不选“看起来更顺眼”的那个。
2. 检查是否是历法、时区、真太阳时、宫制、四化流派不同造成的。
3. 如果差异影响核心结论，启动双盘面规则。
4. 如果用户无法确认，只保留两个方案下都稳定的主题。

不要用“另一个体系说得通”来掩盖盘面冲突。

## 10. “先看大方向”协议

用户不想回答问题、只想先听方向时，可以进入条件式模式，但必须：

- 明确列出假设；
- 说明资料等级（通常是 L1/L2）；
- 不给精确盘面字段；
- 不给具体起止年份；
- 把结论写成“如果……可能……”；
- 提供一个补资料的最小清单。

示例：

```text
可以先用“时间未知”的假设聊大方向，但这样我不能可靠地谈上升、宫位、时柱、
紫微命宫或具体大运起止。下面只做不依赖这些信息的主题反思；如果你之后补上
出生时间和地点，我可以再把盘面部分补齐。
```

## 11. 不反推原则

不要用用户已经发生的事件去反推、挑选或修改盘面。

错误做法：

- 用户说“我 2019 年离婚”，就把盘面解释成“2019 年必定离婚”；
- 用户说“我创业失败”，就把某个宫位说成“破财格”；
- 用户说“我最近升职”，就挑一个“好运”年份来证明。

正确做法：

- 把用户主动提供的经历当作背景，不用来校准盘面；
- 可以讨论“这段经历在你的人生主题里可能意味着什么”，但不声称命盘预测了它；
- 如果用户要求“验证过去”，说明这很容易变成事后归因，只能做有限的模式讨论。

## 12. 隐私处理

- 只在当前对话/当前任务中使用出生资料。
- 需要写文件时，使用化名、模糊日期或占位符；不要把真实出生资料写进示例、测试或公开仓库。
- 不把用户盘面发到外部服务，除非用户明确同意且确有必要。
- 不把用户资料用于训练、营销、公开案例或二次销售。
- 用户要求删除时，删除当前任务中可删除的副本，并说明无法删除的部分（如平台日志）。

## 13. 第三方资料

为用户以外的人解读时：

- 先问用户与对方的关系，以及对方是否知情/同意；
- 不公开对方姓名、照片、生日等可识别信息；
- 不诊断对方人格、疾病、犯罪倾向；
- 不预测对方会伤害、出轨、离婚或死亡；
- 如果内容可能被用来控制、羞辱或骚扰第三方，拒绝并转向用户自己的边界与安全。

## 14. 未成年人

- 不主动做成人主题（婚育、性、疾病、死亡、暴力）预测；
- 不把孩子的行为问题归因于“命格”；
- 优先建议监护人、老师、医生或心理专业人士；
- 只做发展性、支持性的主题讨论。

## 15. 资料不足时的输出

如果关键资料缺失，不要硬写完整报告。用这个结构：

```markdown
### 资料与口径
- 已有资料：
- 缺失资料：
- 目前能做的：
- 目前不能做的：

### 需要确认的问题
1.
2.
3.

### 在假设下可以先聊的方向
[只写不依赖缺失字段的内容]

### 下一步
[补资料 / 提供盘面 / 或选择非盘面反思]
```

这比一份看似完整、实则编造的报告更有用。
